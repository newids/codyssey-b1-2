## 가이드 읽는 법

- **단계**마다 "무엇을 하는지 → 코드 → 화면에서 볼 것" 순서로 적혀 있다.
- 코드 블록 첫 줄의 주석(`// src/App.tsx`)이 고칠 파일이다.
- 코드는 복사해서 붙여도 된다. 대신 붙인 뒤에 **한 줄씩 읽고, "설명해 보기" 질문에 답해 본다.** 이 과정의 목표는 타이핑이 아니라 코드를 읽고 설명하는 것이다.
- 타입 표기(`type Props = {...}`, `: string` 등)는 가이드에 적힌 대로 쓴다. 읽는 법은 [치트시트](../handouts/cheatsheet.md)에 있다.

## 뒤처졌을 때

다음 실습이 시작되는데 앞 실습을 못 끝냈다면, 앞 실습의 완성 코드를 가져와서 바로 합류한다.

```bash
# 예: 실습 3까지 끝난 상태로 맞추기 (실습 4를 시작할 수 있다)
npm run checkpoint lab3
```

- 지금까지 작업한 `src` 폴더는 `src.backup-날짜-시간` 폴더로 옮겨지므로 사라지지 않는다.
- 쓸 수 있는 이름: `starter`, `lab1` … `lab7`
- 완성 코드에는 도전 과제까지 들어 있다. 도전 과제를 건너뛴 사람의 화면과 조금 다를 수 있다.

## 막혔을 때 순서

1. 파일을 저장했는지 확인한다. (`Ctrl + S` / `⌘ + S`)
2. 브라우저 화면의 빨간 오류 창이나 VS Code의 빨간 밑줄에 마우스를 올려 메시지를 읽는다.
3. 각 가이드의 "막혔을 때" 표를 본다.
4. 옆 사람 또는 강사에게 묻는다. 3분 넘게 혼자 붙잡고 있지 않는다.
