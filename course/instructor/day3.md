### 복습 (10분)

### 이론 7 — 폼과 검증 (15분)

라이브 코딩 (6분)

1. `App.tsx`에 임시로 `const [text, setText] = useState('')`와 `<input value={text} onChange={…} />`, 그 아래 `<p>{text}</p>`를 넣는다.
2. 입력하면 아래 글자가 같이 바뀌는 것을 보여 준다.
3. `onChange`를 지워 글자가 안 쳐지는 것을 보여 준다. "입력칸은 state를 보여 줄 뿐이다."
4. 임시 코드를 지운다.

- 제출 슬라이드에서 `preventDefault`를 빼면 어떻게 되는지는 실습 6의 1단계에서 직접 겪게 된다. 미리 "새로 고쳐진다"만 말해 둔다.
- 검증 슬라이드: "오류 메시지도 state, 보여 주는 것은 어제 배운 `&&`"로 연결한다.

예상 질문

- "`event.target.value`가 뭔가요?" → `event`는 방금 일어난 일의 정보, `target`은 그 입력칸, `value`는 입력칸에 지금 들어 있는 글자.
- "입력할 때마다 다시 렌더링하면 느리지 않나요?" → 이 정도는 전혀 문제없다. React는 바뀐 부분만 실제 화면에 반영한다.

### 실습 6 (25분)

| 시간 | 단계 | 방식 |
| --- | --- | --- |
| 0–8분 | 1단계 (입력칸 묶기) | 코드를 붙이고 같이 읽기 |
| 8–15분 | 2단계 (제출) | 각자 |
| 15–25분 | 3단계 (검증) | 각자 |

- 1단계의 폼 코드는 길다. 타이핑하지 않고 붙여 넣은 뒤 `value`/`onChange` 두 줄을 찾아 표시하게 한다.
- 2단계에서 toolbar의 예전 "메모 추가" 버튼을 지우지 않으면 타입 오류가 난다. 가이드의 "막혔을 때"에 있다.
- 3단계의 `textarea` 쪽 오류 표시는 "같은 방법으로"라고만 적혀 있다. 막히는 사람에게는 제목 쪽 코드를 복사해 `title`을 `body`로 바꾸게 한다.

### 이론 8 — useEffect (10분)

1. (2분) 렌더링 바깥의 일: 저장, 요청.
2. (3분) 실행 시점 그림(G8)과 의존성 배열 표.
3. (3분) 상태 전이 그림(G9): 요청에는 로딩·성공·에러가 있고, 성공에도 "0개"가 있다.
4. (2분) 개발 모드에서 두 번 실행되는 것. 실습 중에 Network 탭을 보고 질문이 나오기 전에 미리 말한다.

"요청 코드 읽기" 슬라이드는 실습 7의 5단계 직전에 띄운다.

예상 질문

- "`async/await`은 안 쓰나요?" → 쓸 수 있다. `src/api/tips.ts`가 그렇게 돼 있다. effect 함수 자체는 `async`로 만들 수 없어서 컴포넌트에서는 `.then`을 썼다.
- "의존성 배열에 뭘 넣어야 할지 어떻게 아나요?" → effect 안에서 쓰는 state와 props를 넣는다. 실무에서는 편집기 검사 도구가 알려 준다.

### 실습 7 (25분)

- (a) 저장 10분: 2단계까지 같이 하고, 3단계(개발자 도구에서 값 보기)는 강사 화면으로 보여 준다.

### 이론 9 — 실제 서비스로 넓히기 (15분)

코드를 가르치지 않는다. "이런 것이 있고, 우리가 만든 것의 어느 부분이 이렇게 커진다"를 보여 주는 시간이다.

| 시간 | 내용 | 보여 줄 것 |
| --- | --- | --- |
| 2분 | 메모 앱 → 서비스 대응 표 | 교안 표 |
| 2분 | React Playground 아키텍처 | G10 그림, 다섯 영역을 손으로 짚는다 |
| 2분 | 라우팅 | 사이트에서 메뉴를 눌러 주소가 바뀌는 것, `src/App.tsx`의 `<Route>` 목록 |
| 2분 | 커스텀 훅 | `src/hooks/useAsync.ts` — "실습 7의 TipList와 똑같이 생겼죠?" |
| 3분 | 전역 상태 | 사이트에서 로그인 전후 헤더가 바뀌는 것, `useAuth()` |
| 2분 | 백엔드 | 노트 목록이 다른 기기에서도 보인다는 점, `supabase.from('notes')` 한 줄 |
| 2분 | 배포 | `npm run build` → 파일 묶음 → 주소 |

- 각 항목에서 "메모 앱의 무엇이 이것으로 바뀌는가"를 한 문장으로 말한다.
  - 끌어올린 state + props 전달 → Context
  - localStorage → 데이터베이스
  - `TipList`의 status/effect → `useAsync`
- 마지막에 G1을 다시 띄워 "첫날 본 그림의 나머지 부분"이라고 닫는다.

예상 질문

- "Redux를 배워야 하나요?" → 지금은 아니다. state 끌어올리기와 Context로 부족함을 느낄 때 배운다.
- "Next.js는 뭔가요?" → React 위에 라우팅·서버 기능을 얹은 도구다. React를 알면 읽을 수 있다.
- "백엔드는 꼭 Supabase인가요?" → 아니다. 주소로 요청하고 JSON을 받는다는 점은 어떤 백엔드든 같다.
