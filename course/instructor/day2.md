### 이론 4 — useState와 이벤트 (20분)

라이브 코딩 순서 (10분)

1. `Counter.tsx`를 만들고 `let count = 0`과 버튼으로 시작한다. `App`에 `<Counter />`를 넣는다.
2. 핸들러에서 `count = count + 1; console.log(count);` — 콘솔은 올라가는데 화면은 그대로인 것을 보여 준다.
3. "React에게 바뀌었다고 알려 줘야 한다" → `useState`로 바꾼다.
4. `<Counter />`를 하나 더 넣어 state가 따로 있는 것을 보여 준다.
5. `onClick={handleClick()}`로 바꿔 `Too many re-renders` 오류를 보여 주고 되돌린다.

- 순환 그림(G6)을 띄우고 방금 본 것을 5단계로 다시 말한다. 수강생 한 명에게 따라 말하게 한다.
- "컴포넌트 함수가 다시 실행된다"를 확인시키려면 함수 첫 줄에 `console.log('렌더링')`을 넣어 누를 때마다 찍히는 것을 보여 준다.

예상 질문

- "`setCount(count + 1)` 바로 다음 줄에서 `count`를 찍으면 왜 예전 값인가요?" → set 함수는 "다음에 그릴 때 이 값으로"라는 예약이다. 지금 실행 중인 함수 안의 `count`는 바뀌지 않는다.
- "`const`인데 어떻게 바뀌나요?" → 바뀌는 게 아니라 함수가 다시 실행되면서 새 `count`가 만들어진다.
- 개발 모드에서 `console.log('렌더링')`이 두 번씩 찍히는 것을 물으면: StrictMode가 일부러 두 번 실행한다. 3일 차에 다시 나온다.

### 이론 5 — 배열 state와 끌어올리기 (10분)

1. (2분) 문제 슬라이드: `Header`가 모른다.
2. (3분) 끌어올리기 그림(G7): 데이터는 내려가고, 호출은 올라온다. 화살표를 손으로 따라간다.
3. (4분) "세 가지만 기억한다" 표. `push`가 안 되는 이유는 한 문장만: "React는 같은 배열인지만 본다."
4. (1분) 계산값은 state로 두지 않는다.

"함수도 props로" 슬라이드는 실습 4의 3단계 직전에 띄운다.
