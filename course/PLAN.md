# React 기초 과정 설계 및 문서 작성 계획

2시간 × 3일(총 6시간), React를 처음 접하는 사람을 위한 이론·실습 과정.
이 문서는 (1) 과정 설계와 (2) 교안·실습 자료·가이드의 작성 계획을 담는다.

---

## 1. 과정 개요

| 항목 | 내용 |
| --- | --- |
| 과정명 | React 첫걸음 — 3일 만에 메모 앱 만들기 |
| 시간 | 2시간 × 3일 (매일 10분 휴식 포함) |
| 대상 | React 경험이 없는 사람. HTML 태그와 JS의 변수·함수·배열을 한 번이라도 써 본 수준을 가정 |
| 이론 : 실습 | 약 4 : 6 (하루 이론 45분, 실습 65분, 휴식 10분) |
| 실습 방식 | 3일 동안 하나의 앱(학습 메모 앱)을 단계별로 키워 간다 |
| 도구 | Node.js LTS, VS Code, Vite + React, 언어는 TypeScript(TSX) |
| 시각 자료 | 개념마다 아키텍처 그림을 쓴다 (5절 목록) |
| 보조 교재 | 이 저장소의 React Playground(https://codyssey-b1-2-react.vercel.app) 레슨·퀴즈 |

### 최종 학습 목표

과정을 마친 수강생은 다음을 할 수 있다.

1. 화면을 컴포넌트로 나누고 props로 데이터를 내려보낸다.
2. `useState`로 상태를 만들고, 이벤트가 상태를 바꾸면 화면이 다시 그려진다는 흐름을 설명한다.
3. 배열 상태를 불변하게 추가·삭제·수정하고 `map`으로 목록을 그린다.
4. controlled input으로 폼을 만들고 간단한 검증을 붙인다.
5. `useEffect`로 저장(localStorage)과 데이터 요청을 처리하고, 로딩·에러·빈 상태를 나눠 그린다.

### 범위 결정

6시간 안에 입문자가 소화할 수 있는 양으로 줄였다.

| 다룬다 | 소개만 한다 | 다루지 않는다 |
| --- | --- | --- |
| JSX, 컴포넌트, props | JavaScript와 TypeScript의 차이 (1일 차 8분) | 제네릭 등 TypeScript 심화 문법 |
| useState, 이벤트 | 라우팅(React Router) | 테스트, 성능 최적화 |
| 목록·조건부 렌더링, key | 커스텀 훅 | 서버 컴포넌트, Next.js |
| 불변 업데이트, state 끌어올리기 | 전역 상태(Context, 상태 관리 라이브러리) | 백엔드 직접 구현 |
| controlled input, 검증 | 백엔드 연동(Supabase: 인증, DB) | |
| useEffect, fetch, 로딩/에러/빈 상태 | 배포(Vercel) | |

라우팅부터 배포까지 다섯 가지는 3일 차 마지막 15분에 React Playground의 전체 아키텍처 그림 한 장 위에서 위치를 짚어 가며 소개한다.

### TypeScript를 다루는 방식

수강생이 앞으로 코드를 직접 타이핑할 일은 거의 없다고 보고, 문법을 가르치지 않고 읽는 법만 알려 준다.

- 1일 차에 차이점만 8분 소개한다: TypeScript는 JavaScript에 타입 표기를 더한 것이고, 실행 전에 오류를 잡아 주며, 브라우저에서는 결국 JavaScript로 바뀌어 돌아간다.
- 실습 코드에 나오는 타입은 세 가지로 제한한다: props 타입(`type Props = {...}`), 데이터 모양(`type Note = {...}`), `useState<Note[]>`.
- 타입 선언은 스타터와 가이드에 미리 적어 두고, 수강생은 읽고 붙여 쓰기만 한다. 빨간 줄이 뜨면 메시지를 읽는 법을 실습 가이드의 "막혔을 때"에 넣는다.
- 같은 이유로 실습은 빈 파일에서 타이핑하는 방식보다 주어진 코드를 읽고, 바꾸고, 결과를 설명하는 단계를 늘린다.

### 실습 앱: 학습 메모 앱

React Playground의 "학습 노트" 기능을 축소한 것이다. 수업에서 만든 것이 실제 서비스에서 어떻게 커지는지 바로 비교해 볼 수 있다.

- 1일 차 결과: 메모 카드 목록이 보이는 정적 화면 (컴포넌트 + props)
- 2일 차 결과: 메모 추가·삭제·중요 표시가 되는 화면 (state + 이벤트)
- 3일 차 결과: 입력 검증, 새로고침해도 남는 메모, 외부 데이터 불러오기 (폼 + effect)

### 운영 원칙

- 이론은 한 번에 20분을 넘기지 않고, 바로 뒤에 그 내용을 쓰는 실습을 붙인다.
- 실습마다 "여기까지 되면 성공" 확인 항목을 두고, 뒤처진 사람은 다음 단계의 시작 코드를 받아 바로 합류한다.
- 각 실습에는 필수 단계와 도전 과제를 나눠 속도 차이를 흡수한다.
- 자주 나는 오류(닫지 않은 태그, `class`/`className`, `key` 경고, state 직접 수정)는 강사가 일부러 재현해서 에러 메시지 읽는 법을 보여 준다.

### 실습 가이드 공통 형식 (D5)

1. 이번 실습에서 만드는 것 (완성 화면 캡처)
2. 시작 상태 (어느 체크포인트에서 출발하는지)
3. 단계별 진행: 지시 → 코드 → 저장 후 화면에서 볼 것
4. 확인 항목 (체크박스 3–5개)
5. 막혔을 때 (자주 나는 오류와 메시지 읽는 법)
6. 도전 과제 (선택)

## 4. 작성 순서

코드가 기준이 되어야 문서가 어긋나지 않는다. 그래서 코드 → 실습 가이드 → 교안 → 나머지 순으로 쓴다.

| 단계 | 작업 | 산출물 | 완료 기준 |
| --- | --- | --- | --- |
| 1 | 최종 완성본을 먼저 만든다 | `code/checkpoints/lab7/` | 빌드 성공, 3일 차 결과 기능이 모두 동작 |
| 2 | 완성본을 실습 단위로 거꾸로 자른다 | `code/memo-app/`, `code/checkpoints/starter, lab1–7/` | `npm run verify`로 모든 체크포인트가 타입 검사와 빌드를 통과한다 |
| 3 | 실습 가이드를 쓴다 | `labs/lab0–7.md` | 가이드만 보고 앞 체크포인트에서 다음 체크포인트가 만들어진다 |
| 4 | 아키텍처 그림을 그리고 교안을 쓴다 | `slides/diagrams/`, `slides/day1–3.md` | 실습에 나오는 모든 개념이 그 실습보다 앞 슬라이드에 있다. 그림 속 이름이 실습 코드의 컴포넌트·파일 이름과 같다 |
| 5 | 강사용 노트와 오류 대응집을 쓴다 | `instructor/` | 진행표의 시간 합이 하루 120분 |
| 6 | 배포 자료를 쓴다 | 개요서, 준비 안내, 치트시트, 퀴즈, 다음 단계, 설문 | 용어와 코드가 교안·실습과 일치 |
| 7 | 검증한다 | 수정 반영본 | 아래 검증 항목 통과 |

### 검증 항목

- `npm run verify`로 모든 체크포인트의 타입 검사와 빌드 성공.
- 그림 10종이 밝은 화면과 어두운 화면, 프로젝터 해상도에서 읽히는지 확인.
- 실습 가이드를 처음부터 그대로 따라 해서 최종본과 같은 동작이 나오는지 확인.
- 실습별 소요 시간 측정. 작성자가 걸린 시간의 3배가 배정 시간 안에 들어와야 한다.
- 교안·가이드·치트시트의 용어 통일(상태/state, 속성/props 등 표기 규칙 하나로).
- 가능하면 입문자 1명에게 1일 차 분량을 시험 진행해 막히는 지점을 고친다.

## 6. 확인이 필요한 결정

아래는 기본값으로 계획을 세웠다. 다르면 해당 부분만 바꾸면 된다.

| 결정 | 기본값 | 바뀌면 달라지는 것 |
| --- | --- | --- |
| 수강생 선수 지식 | HTML·JS 기초는 안다 | JS를 모르면 1일 차 앞에 JS 복습 30분을 넣고, 3일 차 외부 데이터 실습을 뺀다 |
| 실습 환경 | 각자 노트북에 설치, 실패 시 StackBlitz | 전원 브라우저 환경이면 준비 안내가 1쪽으로 줄어든다 |
| 교안 형식 | 마크다운(발표는 슬라이드로 변환) | PPT나 HTML 슬라이드가 필요하면 4단계 작업량이 늘어난다 |
| 진행 형태 | 대면, 20명 안팎, 조교 1명 | 비대면이면 확인 항목 제출 방식과 질문 채널을 추가한다 |
